# 열수송관 열화상 이상 후보 비교 실험

[통합 연구 계획](RESEARCH_PLAN.md) · [2026-11-17 진행 현황](PROGRESS_2026-11-17.md) · [후속 비교 결과](RESULTS_2026-11-17.md) · [ΔT와 추적 영상 검토](VISUAL_REVIEW_2026-11-17.md) · [상위 50건과 인접 열원 검증](VEHICLE_AND_TRACKING_REVIEW_2026-11-17.md) · [실증 촬영 독립 평가 프로토콜](HELDOUT_PROTOCOL_2026-11-18.md) · [독립 평가 결과](HELDOUT_RESULTS_2026-11-18.md)

이 폴더는 현재 `heatpipe_service` 분석 파이프라인의 후보 품질과 처리 성능을 비교하기 위한 **비배포 실험 코드**를 둔다. `../heat-pipe`는 기존 PoC와 과거 결과 비교용이다. 이 폴더의 방법은 검증 전까지 운영 `src/` 코드나 API 응답 정책을 바꾸지 않는다. 원본 ATT·ATG와 생성 결과는 Git에 넣지 않는다.

첫 두 쌍의 측정값과 해석은 [2026-11-16 E0~E3 결과](RESULTS_2026-11-16.md)에 기록했다. 나머지 12쌍은 `run_remaining.py`로 각 ATT 전체 프레임에 E0~E2를 순차 실행했다. `aggregate_14_pairs.py`는 14쌍의 42개 실행 결과와 출력 건수를 대조해 `output/experiments/overnight-20261116-v2/REPORT_14_PAIRS.md`를 생성했다. 해당 출력 경로는 Git에서 제외된다.

14쌍의 ATT는 148,742프레임이지만, 세 파일(`20260812_203339`, `20260815_095210`, `20260817_094744`)의 대부분이 0값뿐인 빈 프레임이다. 실제 분석된 프레임은 총 108,766개이며 전체 촬영 구간 비교에 쓸 수 있는 파일은 11쌍이다. 파일별 프레임 수와 E0~E3 결과는 위 최종 보고서를 확인한다. 현장 정답 위치나 검토 라벨이 없어 후보 정확도·누수 재현율은 계산하지 않았다.

## 폴더와 실행 범위

```text
heat-pipe-service/
  experiments/
    README.md
    compare_methods.py       # 현재 서비스 방식의 재현 가능한 기준선 실행
    summarize_e0.py          # 상한 전 트랙과 반환 후보의 분포 요약
    compare_selection.py     # E3 점수순과 10구간 선정 비교
    run_remaining.py         # 나머지 12쌍의 E0~E2 전체 프레임 순차 실행
    aggregate_14_pairs.py    # 14쌍 집계와 출력 건수 검증
  output/experiments/        # 실행별 JSON·CSV·PNG; Git 제외
```

`compare_methods.py`는 현재 방식(`baseline`), E1의 **MAD=0 대체값 시험안**(`nonzero_mad_fallback`), E2의 **중간 1프레임 누락 허용 시험안**(`gap_one_missing`)을 실행할 수 있다. E1은 MAD가 0에 가까우면 0이 아닌 잔차의 중앙 절대편차를 사용하며 최소 분모를 0.05℃로 둔다. E2는 점수 계산을 유지하고 트랙 연결에서 허용하는 프레임 번호 차이만 1에서 2로 늘린다. 모두 **실험용 가정**이며 운영 기본값으로 확정한 것이 아니다. 반환 상한 전 적격 트랙의 특징과 모든 연결 지점을 `eligible_tracks.jsonl.gz`에 별도로 저장한다. 서비스의 비공개 함수를 실험 실행 중에만 감싸서 내보내므로 운영 코드는 수정하지 않는다. 이 외의 새 점수·추적·모델 실험은 아직 구현되지 않았다. 검토 라벨이 없으면 전체 트랙 목록만으로 누락률을 계산할 수는 없다.

## 시작 전 준비

1. 원본 ATT·ATG의 동일 파일명 쌍과 읽기 전용 경로를 준비한다. 현재 확인된 전체 파일은 ATT 3,959프레임, ATG 3,885레코드로 개수가 다르다. ATG 시각·GPS를 정답 위치로 간주하지 않는다.
2. 실험 버전, 입력 파일 식별값, 장치, ROI, 프레임 범위, 파라미터, 실행 시간, 최대 메모리, 결과 경로를 실행별로 기록한다. 비교할 때는 입력·프레임 범위·ROI·반환 상한을 동일하게 유지한다.
3. 검토용 라벨을 **트랙 또는 실제 노면 지점 단위**로 만든다: `관로 이상 의심`, `차량/배기열`, `기타 노면 열원`, `판단 불가`. 가능하면 확인된 보수·현장 점검 결과를 별도 근거로 연결한다. 미확인 의심 후보를 확정 누수로 표시하지 않는다.
4. 상위 후보뿐 아니라 전 구간·낮은 점수·후보가 없는 구간도 표본 검토한다. 같은 지점이 여러 프레임에 등장하면 하나의 사건으로 묶는다. 학습·평가 자료는 인접 프레임 단위가 아니라 **촬영 회차/날짜/노선** 단위로 분리해 중복 장면이 양쪽에 들어가지 않게 한다.

## 실행 가능한 기준선

기존 `heat` 가상환경을 사용해 `heat-pipe-service`에서 실행한다. 스크립트는 이 저장소의 `src/`를 직접 참조하므로 서비스를 별도로 설치할 필요는 없다. 출력 경로는 **매 실행 새 디렉터리**로 지정한다. 전체 파일은 시간과 디스크 공간이 필요하므로 먼저 짧은 구간으로 실행할 수 있다.

```powershell
& '..\heat\Scripts\python.exe' experiments/compare_methods.py `
  --att 'C:\path\to\sample.att' --atg 'C:\path\to\sample.atg' `
  --frame-end 100 --output 'output/experiments/baseline-001'
```

출력의 `detected_candidate_count`는 반환 상한 전 **적격 트랙 수**이고 `candidate_count`는 실제 반환 수다. 진행률과 요약은 콘솔에 표시하며 `experiment_summary.json`에도 요약을 저장한다. 상세 결과는 출력 경로의 `analysis_result.json`, `analysis_candidates.csv`, `images/`, `eligible_tracks.jsonl.gz`에 저장된다. 작은 구간에서 후보가 0건일 수 있다. 실패 시 요약의 `status`와 결과 JSON의 오류를 확인한다.

## 최적화 실험 조합

`--method optimized_vehicle`는 E1 점수 안정화, 현행 트랙 연결, ΔT와 형상·지속성 특징을 이용한 차량 재순위를 한 번에 실행한다. E1 지속성 점수를 파일 내 백분위로 바꾸고 `0.05 × 차량 점수`를 뺀다. 이 점수로 정렬한 뒤 동일한 10구간 선정과 반환 상한을 적용한다. 외부 평가 날짜는 차량 점수 학습에서 제외한다. 기존 오프라인 비교와 통합 실행은 같은 학습·특징·재순위 코드를 사용한다.

이 실행은 ATT를 읽기 전용 배열로 한 번 열고, 프레임 ROI의 기울기를 연결 영역 사이에 재사용한다. `vehicle_selection.json`에는 감점 전후 트랙 ID와 학습 집계가 들어간다. `eligible_tracks.jsonl.gz`의 원래 E1 순서는 그대로 유지되며 각 행에 ΔT를 포함한 특징, 차량 점수, 감점 후 정렬 점수를 추가한다. 결과 JSON과 PNG에는 최적화 방식에서 선정된 후보가 담긴다.

```powershell
& '..\heat\Scripts\python.exe' experiments/compare_methods.py `
  --method optimized_vehicle --device cpu `
  --att 'C:\path\to\sample.att' --atg 'C:\path\to\sample.atg' `
  --vehicle-features 'output/experiments/reranking-20261117-v2/track_features.jsonl.gz' `
  --vehicle-labels 'output/experiments/visual-review-20261117-v2/rank_observations.json' `
  --output 'output/experiments/optimized-001'
```

통합 실행은 합성 8프레임에서 출력 생성을 확인했다. 실증 자료를 이용한 최종 후보 품질과 처리 시간 비교는 별도 검증 단계다.

## 실험 목록과 순서

| 순서 | 실험 | 비교 방법 | 확인할 결과 |
|---|---|---|---|
| E0 | **현재 방식 기준선·전체 트랙 내보내기** | 코드·설정 고정 후 전체 파일 재실행. 반환 상한 전 트랙의 프레임 범위·대표 위치·세 알고리즘별 점수·면적·온도 대비를 실험 산출물로 저장 | 전체 트랙 수, 10개 구간별 분포, 상위 50건 집중도, 점수 분포, 처리 시간·메모리·PNG 용량 |
| E1 | **상대 온도와 점수 안정화** | 현재 `MAD + 1e-6` 점수와, MAD가 작은 프레임의 분모 하한·주변 노면 대비 온도(℃)·강도 요약을 비교. 130℃ 값은 장비 상한 확인 전 자동 제외하지 않음 | 점수 폭주 감소, 차량 후보 순위 변화, 확인된 이상 재현율 유지 여부 |
| E2 | **프레임 연결과 지면 고정성** | 현행 중심거리 탐욕 연결과 누락 1프레임 허용, 이동·크기·겹침 특징을 추가한 연결을 순차 비교 | 트랙 분리·병합 오류, 동일 지점 중복, 차량 후보와 노면 후보의 순위 변화 |
| E3 | **반환 50건 선정 정책** | 전체 점수순 50건과 현재 10개 시간 구간 순환 선정, 동일 지점 중복을 제한한 선정을 비교 | 알려진 이상 위치의 Recall@50, 구간별 누락, 검토할 중복 건수. 50건은 현재 임시 상한 |
| E4 | **트랙 특징 기반 비지도 재순위** | E0의 트랙 특징으로 Isolation Forest, LOF를 각각 학습·평가하고 현재 순위와 비교. 이상 확정 판정기로 사용하지 않음 | 차량·기타 열원 오탐 감소 여부, 새로운 촬영 회차에서의 순위 안정성 |
| E5 | **차량 열원 분류** | 검토 라벨이 쌓이면 열화상 후보 패치 또는 이용 가능한 RGB 자료로 차량/배기열 분류 점수를 만들고 기존 후보 순위에 결합 | 차량 오탐 감소와 실제 노면 이상 누락의 교환 관계. 불확실한 후보는 보존 |
| E6 | **재구성 모델·객체 탐지 모델** | 정상 데이터와 현장 확인 라벨이 충분할 때만 CAE/U-Net 또는 지도 객체 탐지를 동일 평가셋에서 비교 | E1~E5 대비 추가 이득, 추론 시간, 다른 날짜·노선으로의 일반화 |
| E7 | **처리 성능** | 품질 설정을 고정하고 ATT 연속 읽기, 연결 영역 특징 계산 중복 제거, CPU/GPU 전송 방식 등을 하나씩 비교 | 동일 후보·점수 허용 오차 안에서 전체 소요 시간과 최대 메모리. 4 vCPU/4 GB 시험 서버에서도 별도 측정 |

E1~E3을 먼저 수행한다. E4~E6은 라벨과 여러 촬영 회차가 준비된 뒤 진행한다. 센서 시계열용 LSTM·ARIMA나 실시간 FPS 최적화는 현재 ATT 배치 분석의 우선 과제가 아니다.

## 공통 평가 기준

- **후보 품질:** 현장 확인 정답이 있는 지점의 `Recall@50`, 상위 50건 중 검토 가치가 있는 지점 비율, 차량/배기열 오탐 건수, 동일 지점 중복 건수. 확인된 이상 정답이 없으면 재현율을 계산하거나 성능 향상을 주장하지 않는다.
- **공간·시간 분포:** 촬영 범위 10개 구간별 적격 트랙·반환 후보 수, 시작·끝 구간 누락, 같은 시각·GPS의 서로 다른 열원 여부. GPS만으로 중복 또는 차량 여부를 결정하지 않는다.
- **운영 성능:** 입력 다운로드·분석·PNG 생성 시간을 분리해 기록하고 최대 메모리·디스크 사용량을 측정한다. 로컬 GPU와 시험 서버 CPU 결과를 직접 속도 비교하지 않는다.
- **채택 조건:** 동일 평가셋에서 알려진 이상을 더 놓치지 않으면서 검토할 차량·중복 후보를 줄이거나, 후보 품질을 유지하며 처리 비용을 낮출 것. 후보·PNG 계약 변경이 필요하면 API와 문서 검토를 별도로 진행한다.
