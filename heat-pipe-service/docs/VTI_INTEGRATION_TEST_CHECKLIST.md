# DaonH&S 측 VTI 연동 시험 준비 체크리스트

- 기준일: 2026-11-06
- 범위: [Q15 연동 API 명세 v1.0](Q15_VTI_INTEGRATION_API_FINAL.md)과 INT-001·003·004 개발 범위
- `[x]`는 현재 확인된 사실, `[ ]`는 연동 시험 전에 완료하거나 양측이 확정할 항목이다.
- 이 문서는 DaonH&S의 준비·확인 항목이다. 로컬 `[x]`는 **VTI 서버와의 연동 통과**를 뜻하지 않는다. VTI 측 확인 항목과 양측의 연동 완료 기준은 VTI 회신을 받은 뒤 함께 정한다.

## VTI 연동 시험 전 완료

- [ ] **VTI 실제 파일 전달:** 로컬 모의 HTTPS URL 검증은 완료했다. 검증한 ATT 한 건은 875,667,464 bytes(약 875.7 MB)이며 회차당 최대 크기는 미확정이다. VTI가 실제 ATT·ATG를 MinIO에 업로드하고 각 파일의 Presigned HTTPS GET URL을 INT-003에 제공할 때, DaonH&S 시험 서버에서 해당 호스트 접근 및 실파일 다운로드를 다시 시험한다. 추가 파일 크기를 확인해 서버 용량·크기 상한을 협의한다.
- [ ] **ATG 시각·GPS 의미:** 현재 후보 `captured_at`은 ATG 장비 시각을 KST로 가정해 `+09:00`을 붙인다. DaonH&S가 실제 장비 시간대를 확인한다. ATG 레코드가 없는 대표 프레임에서는 시각·GPS가 함께 null인지 확인하고, GPS 신호 없음의 ATG 표기 방식은 별도 샘플로 확인한다. 포털의 회차명은 후보별 `captured_at`에서 만들지 않는다.
- [ ] **R2-05 프레임·GPS 정합:** ATT 프레임별 시각 또는 별도 동기화 로그, ATG 레코드 누락 위치, 장비 시각대·GPS 갱신 규칙, 기준 위치를 확보한다. 3,959 대 3,885의 74건 차이가 어디서 발생했는지 확인하고 시각 기준 결합 가능성을 판단한다. 기준 위치와 비교한 거리 오차를 측정하기 전에는 5m 최근접 관로를 확정 자동 귀속하지 않는다.
- [ ] **URL 수명·무결성:** 현재 분석 워커는 매 재시도에 ATT·ATG를 다시 내려받는다. DaonH&S 연동 기준으로 요청한 24시간 유효기간이 VTI의 실제 Presigned URL 발급 설정에 적용되는지 확인한다. 대기·다운로드·최대 3회 시도를 포함해 시험하고, 크기/SHA-256 제공 여부 및 URL 만료·잘못된 파일·접근 거절 때 INT-004 오류를 확인한다.
- [ ] **전체 구간 후보 품질:** API→분석 워커 경유 전체 구간과 PNG HTTP 조회는 확인했다. 차량 부근에 상위 후보가 집중되므로 후보 품질을 검토한다.
- [ ] **R2-01 상한·구간 분포:** 10개 프레임 구간의 균등 기회 선정과 상한별 결과를 실제 ATT·ATG 전체 3,959프레임으로 재실행한다. 상한 전 적격 트랙 수, 구간별 후보 수, 대표 프레임·시각·GPS 중복, PNG 수·총 크기, 작업 시간과 7일 저장 공간을 기록한 뒤 UAT용 상한을 확정한다. 포털의 1,000건은 허용 한도다. 차량 부근 자동 제외는 라벨 검토 후 판단한다. 이전 50건 샘플·측정값을 새 정책의 근거로 사용하지 않는다.
- [ ] **R2-02 전체 후보 수:** 새 실데이터 결과에서 `processing.parameters.max_results`와 `detected_candidate_count`가 기록되고, `candidate_count = min(detected_candidate_count, max_results)`인지 확인한다. 포털에서 두 건수로 잘림 여부를 구분하는지 검증한다. 이전 저장 결과의 null은 미확인으로 취급한다.
- [ ] **R2-07 ROI 온도 필수:** 앞으로 INT-003으로 접수한 작업의 INT-001 결과에서 모든 후보의 `roi_temperature_c`가 객체인지 확인한다. 누락·null 결과는 워커가 `SUCCEEDED`로 저장하지 않는지 검증한다. 이전 저장 결과의 null은 신규 작업 계약과 구분한다.
- [ ] **R2-13 배포 경로:** 시험 전 VTI가 제공한 HTTPS Presigned URL 호스트를 API·워커 허용 목록에 등록하고 재시작한다. 최종 동일 서버 배포에서는 포털 백엔드→분석 API, 분석 워커→MinIO를 공유 Docker 내부망의 HTTP 서비스 주소로 연결하고 MinIO 호스트만 내부 HTTP 허용 목록에 등록한다. 워커 컨테이너에서 서명 경로·쿼리 전달·리다이렉트 없는 GET을 확인한다. 원본 ATT·ATG의 서로 다른 Object Key가 한 작업으로 처리되는지 확인하고 API·워커 로그에서 URL 서명 노출 여부를 점검한다.
- [ ] **시험 서버 전체 실파일·용량:** 현재 시험 서버는 CPU 워커로 실행 중이다. VTI ATT·ATG 전체 파일의 다운로드·분석 시간, 메모리·디스크 사용량 및 임시 파일 정리를 확인한다. GPU 사용 가능 여부가 확인되면 별도로 가속 배포를 검토한다. 로컬 CPU·GPU 전체 파일 검증값을 시험 서버 성능으로 해석하지 않는다.
- [ ] **접근망·인증:** DaonH&S 측 외부망에서 `https://heatpipe.daonhns.com`의 HTTPS 443과 Bearer 인증은 확인했다. VTI 시험망에서 같은 주소의 접속·인증을 확인하고, 분석 워커의 VTI MinIO HTTPS 접근 및 출발 IP `211.60.149.76`의 허용 목록 적용을 확인한다. 최종 동일 서버 배포에서는 이용자용 포털 도메인과 포털 백엔드→분석 API의 공유 Docker 내부망 경로, 워커에서 접근 가능한 MinIO URL 호스트를 양측 배포 구성에 맞춰 확인한다. Bearer 키는 별도 보안 채널로 전달하고 양측 서버 환경에만 보관한다. VTI 백엔드의 PNG 중계 경로를 정하고 호출한다. VTI 시험 서버에서 `/health`의 `worker_running`·`worker_last_activity_at`·`queued_job_count`를 확인한다.
- [x] **운영 문서 경로:** 시험 서버의 공개 HTTPS 주소에서 `/docs`·`/redoc`·`/openapi.json`은 404이고 `/health`·`/version`은 정상 응답함을 확인했다. OpenAPI는 정적 파일로 전달한다.
- [ ] **완료 확인:** INT-004 10초 폴링과 포털의 임시 대기 한도(`QUEUED` 6시간·실행 3시간)를 VTI와 합의한다. 시간 초과는 포털의 처리 지연 안내로 표시하고 작업의 실제 `FAILED`와 구분하며, 동일 `job_id` 재조회·자동 재시도 시 상태 전환을 시험한다. VTI MinIO·시험 서버에서 전체 파일 소요 시간을 측정해 한도를 다시 검토한다. 현재 콜백과 분석 워커의 강제 실행 시간 제한은 구현되어 있지 않다.
- [ ] **대기 순번:** VTI 포털이 `QUEUED`에서 `queue_position`을 앞선 대기 건수로 표시하고, 실행 중에는 숨기며 예상 완료 시간으로 해석하지 않는지 확인한다.
- [ ] **작업 취소:** VTI 포털에서 대기·실행 중 작업의 취소 API 호출, `cancel_requested=true` 표시 후 `CANCELLED` 도달, 결과 조회 409, 재시도 방지를 시험한다. 포털의 시간 초과 자체로 취소 API를 자동 호출할지는 VTI와 운영 정책을 정한다.
- [ ] **식별자·재요청(R2-09):** VTI의 `monitoring_data_id` 형식, `job_id` 저장, `Idempotency-Key` 생성·재전송 및 409 처리를 VTI 백엔드와 시험한다. 응답 유실 때 같은 키와 동일 `monitoring_data_id`·ATT/ATG 크기·해시를 유지한 채 새 Presigned URL을 발급해도 기존 `job_id`가 반환되는지 확인한다. 대기 중 URL 갱신과 실행 중 URL 고정, 비교값 변경 시 `IDEMPOTENCY_KEY_CONFLICT`, 서버 재기동 후 유지도 확인한다. 최종 `FAILED` 후 재분석은 새 키를 사용한다.
- [ ] **결과·보관:** VTI가 INT-001 JSON과 상대 PNG 경로를 Bearer 인증으로 읽고 후보 ID를 유지하는지 확인한다. `SUCCEEDED`의 `completed_at`부터 JSON·모든 후보 PNG를 최소 7일 보관한다. 시험 서버의 영속 볼륨·디스크 여유·복구 절차를 확인하고 7일 이내 삭제를 방지한다. 7일 이후 삭제 시점은 서버 용량과 운영 정책을 확인해 정한다.
- [ ] **후보 PNG:** VTI 시험 서버의 실제 결과에서 모든 `candidates[].result_image.path`가 PNG 200으로 조회되는지 확인한다. 저장소 장애 시 503 처리와 결과 보관 기간을 함께 시험한다.
- [ ] **PNG 무결성:** VTI가 내려받은 PNG 응답 바이트의 SHA-256·크기를 `result_image.sha256`·`size_bytes`와 비교하고 불일치 시 저장을 중단하는지 시험한다.
- [ ] **양측 통합:** VTI 백엔드에서 정상 한 건과 입력 오류·다운로드 실패·분석 실패·결과 미준비 시나리오를 실행하고 OpenAPI·Q15 문서의 최종 차이를 반영한다.

`object_key`만 전달하는 방식이나 DaonH&S의 결과 MinIO 업로드를 선택할 때에만 공유 저장소 권한·실제 MinIO 서버 검증 항목을 추가한다. GIS/SHP, INT-002·005는 이 체크리스트 범위 밖이다.
