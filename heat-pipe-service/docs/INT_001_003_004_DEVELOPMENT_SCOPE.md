# DaonH&S 연동 INT-001·003·004 개발 범위

- 기준일: 2026-10-30
- 목적: VTI 포털과 DaonH&S 열화상 이상징후 분석 서비스의 개발·연동 범위 정의
- 상태: 2026-10-30 VTI 주간회의 결과를 반영한 현재 범위 기준
- 후속 산출물: 2026-11-06 연동 API 명세

## 1. 확정된 범위 변경

VTI가 SHP 파일을 사용하고 GPS–관로 매칭을 직접 수행한다. 따라서
DaonH&S는 이상징후 분석과 분석 작업 연동만 담당한다.

DaonH&S가 제공할 API는 다음 세 가지다.

- INT-003: ATT·ATG 참조정보를 이용한 분석 작업 요청
- INT-004: 분석 작업 상태·오류 조회
- INT-001: 완료된 이상징후 분석 결과 조회

INT-002와 INT-005는 제공하지 않는다.

## 2. 전체 처리 흐름

1. VTI가 ATT·ATG 파일을 합의된 저장소에 저장한다.
2. VTI가 INT-003으로 파일 참조정보, 모니터링 데이터 ID, 분석 대상 구간,
   ROI를 전달한다.
3. DaonH&S가 분석 작업을 생성하고 `job_id`를 반환한다.
4. DaonH&S가 ATT·ATG를 읽어 이상징후 후보를 분석하고 결과 이미지를 생성한다.
5. VTI가 INT-004로 작업 상태와 진행 상황을 확인한다.
6. 작업 완료 후 VTI가 INT-001로 후보 목록과 분석 결과를 조회한다.

## 3. 시스템별 책임

| 영역 | DaonH&S | VTI |
|---|---|---|
| ATT·ATG 이상징후 분석 | 담당 | 분석 요청 및 결과 사용 |
| 분석 작업 ID·상태·오류 | 생성·제공 | 조회·표시 |
| 이상징후 후보 ID | 생성 방향 제안 | 원본 ID 유지·업무 데이터 연결 |
| 결과 JSON·PNG | 생성·저장 | 조회·화면 표시 |
| ATT·ATG 원본 보관 | 저장소 접근 | 저장 및 참조정보 제공 |
| SHP·관로 공간정보 | 미담당 | 담당 |
| GPS–관로 매칭 | 미담당 | 담당 |
| 미귀속·최근접 관로 판정 | 미담당 | 담당 |
| 후보의 최종 업무 판정 | 분석 후보만 제공 | 사용자 판정·상태 관리 |

후보 ID 생성 주체는 DaonH&S를 기본안으로 제안하되, 최종 정책은 11월 6일
API 명세 협의 시 확정한다.

## 4. INT-003 — 분석 작업 요청

### 목적

VTI가 저장한 ATT·ATG의 참조정보와 분석 조건을 전달하고 비동기 분석 작업을
생성한다.

### 제안 엔드포인트

```http
POST /api/v1/analysis-jobs
```

### 입력 범위

- 모니터링 데이터 ID
- ATT 파일 참조정보
- ATG 파일 참조정보
- 분석 대상 프레임 또는 시간 구간
- 분석 ROI
- 필요시 파일 크기와 체크섬

ATT 파일은 약 770MB이므로 API 요청 본문으로 직접 전송하지 않고, VTI가
저장한 파일의 Object Key 또는 접근 URL을 전달하는 방식을 기본안으로 한다.
저장소 종류, 인증 및 Object Key 규칙은 확정이 필요하다.

### 응답 범위

- `job_id`
- `monitoring_data_id`
- 접수 상태
- 작업 생성 시각

## 5. INT-004 — 작업 상태·오류 조회

### 목적

VTI가 분석 작업의 현재 상태, 진행률 및 실패 정보를 확인한다.

### 제안 엔드포인트

```http
GET /api/v1/analysis-jobs/{jobId}
```

### 제안 상태값

- `QUEUED`
- `VALIDATING`
- `DOWNLOADING`
- `ANALYZING`
- `RENDERING`
- `UPLOADING`
- `SUCCEEDED`
- `FAILED`
- `CANCELLED`

### 응답 범위

- `job_id`
- 작업 상태
- 진행률(0~100%)
- 처리 프레임 수와 전체 프레임 수
- 상태 설명
- 생성·시작·완료 시각
- 실패 시 오류 코드와 메시지
- 시도 횟수, 취소 요청 여부, 실패 오류의 재시도 가능 여부

작업 취소는 `POST /api/v1/analysis-jobs/{jobId}/cancel`로 요청한다. 대기 작업은 즉시 `CANCELLED`가 되고, 실행 중 작업은 분석 워커의 중단 지점에서 종료된다. 취소 접수 직후에는 INT-004로 최종 상태를 확인한다.

분석 완료 확인 방식은 INT-004를 일정 주기로 조회하는 폴링 방식을 기본안으로
한다. 콜백 방식과 진행률 상세 정책은 11월 6일 API 명세에서 확정한다.

## 6. INT-001 — 이상징후 분석 결과 조회

### 목적

완료된 분석 작업의 이상징후 후보와 결과 이미지 정보를 제공한다.

### 제안 엔드포인트

```http
GET /api/v1/analysis-jobs/{jobId}/results
```

후보 PNG 제공 기본안은 같은 DaonH&S API의 하위 경로를 사용한다.

```http
GET /api/v1/analysis-jobs/{jobId}/images/{candidateId}
```

INT-001의 `result_image.path`는 이 상대 API 경로를 반환한다. VTI는 결과 저장소나 MinIO 버킷에 직접 접근하지 않고 DaonH&S API에서 JSON과 PNG를 조회한다.

### 응답 범위

- 스키마 버전
- `job_id`
- `monitoring_data_id`
- 분석 성공·실패 상태
- 분석 대상 및 처리 프레임 정보
- 후보 건수
- 후보별 ID와 검토 순위
- 대표 프레임, 촬영시각 및 GPS
- 분석 ROI와 후보 영역 좌표
- 후보 영역 온도와 주변 대비 온도차
- 탐지 알고리즘·이상점수·지속성 근거
- 결과 PNG의 DaonH&S API 상대 경로(현재 기본안)
- 경고 및 오류 정보

결과 PNG는 DaonH&S가 열화상 원본 해상도 384×288로 생성하며, 2×3 격자와
이상징후 후보 영역을 포함한다.

- API 버전 관리

- 비동기 분석 작업 Queue
- 동시 작업 수 제한
- 작업 상태·진행률 영속 저장
- 서버 재시작 시 상태 복구
- 실패·시간초과·재시도 정책

### 저장소

- VTI가 저장한 ATT·ATG 접근
- 결과 JSON·CSV·PNG 저장
- Object Key 규칙
- 결과 보관기간과 삭제 정책

### 배포·검증

- 개발·운영 환경 분리
- Docker 실행환경
- 실행 로그
- 단위·통합·연동 테스트
- 설치·운영 문서

## 8. 명시적 제외 범위

- INT-002 GIS/SHP 매칭 결과 API
- INT-005 관로 GeoJSON API
- SHP·DBF·PRJ 파싱
- SHP→GeoJSON 변환
- 관로 공간 계산 및 캐시
- GPS–관로 최근접 매칭
- 미귀속 후보와 최근접 관로 거리 산출
- 관로별 최종 이상 확정 건수 집계

위 기능과 데이터는 VTI 포털 범위이며 DaonH&S API에 포함하지 않는다.

- ATT·ATG 전달 방식과 저장소 접근정보
- 분석 완료 확인 방식: 콜백 또는 상태조회
- 상태값, 진행률 제공 여부 및 계산 기준

- `job_id` 형식과 요청 재시도·중복 방지 정책
- 결과 PNG를 DaonH&S API 상대 경로로 제공하는 현재 기본안의 연동 확인
- 분석 구간과 ROI 좌표 형식
- 인증 방식
- 오류 코드와 HTTP 상태 코드
- 폴링 사용 시 권장 주기
- API 명세와 테스트 엔드포인트 제공 범위

현재 구현 기본안은 파일 참조 방식, INT-004 상태조회 기반 폴링, 진행률 제공,
DaonH&S 후보 ID 생성이다. 이 내용은 API 명세 협의 전까지 제안 상태로 본다.
