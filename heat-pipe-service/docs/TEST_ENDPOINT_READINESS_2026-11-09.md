# 11월 9일 INT-001·003·004 시험 엔드포인트 준비표

기준일: 2026-11-05. 이 문서는 [Q15 API 명세](Q15_VTI_INTEGRATION_API_FINAL.md)의 **시험 서버 접속 준비**를 위한 내부 작업표다. 대외 회신 일정은 11월 6일 INT-001~005 API 명세 제공, 11월 9일 INT-001·003·004 실제 엔드포인트 제공 목표, 11월 13일 INT-002·005 실제 엔드포인트 제공 목표, 11월 16일부터 전체 통합 연동 시험 가능 예정이다. 이 저장소의 구현 범위는 INT-001·003·004다. 로컬 Docker 검증과 시험 엔드포인트 제공, 전체 통합 연동 시험은 각각 확인한다.

일정 확인 필요: VTI의 2차 검토의견 시트는 ‘확정본 반영 필요(6건)’을 **11/13 연동 시험 일정에 직접 영향**이 있는 항목으로 설명한다. 이는 DaonH&S가 최초 회신한 ‘11/13 INT-002·005 엔드포인트 제공, 11/16부터 전체 통합 연동 시험’과 다르게 읽힌다. 11/13에 일부 API 접속 시험을 시작한다는 뜻인지, 전체 통합 시험 시작일이 변경된 것인지 VTI에 확인한다. 확인 전에는 11/13을 전체 통합 시험 확정일로 표기하지 않는다.

## 11월 6일 개발 서버 정보 수신

개발 이사님이 공유한 값은 **서버 설치 정보**이며, 아직 VTI가 호출할 HTTPS API 엔드포인트는 아니다. 접속 계정의 비밀번호는 이 문서와 VTI 전달 자료에 기록하지 않는다.

| 항목 | 현재 확인된 값 |
|---|---|
| 가상 서버 | 사내 주소 `192.168.0.50`, Ubuntu 26.04 LTS, 4코어·메모리 4 GB·디스크 32 GB, Docker 설치 |
| 외부 호스트명 | `daonhns.iptime.org` 공유. 실제 DNS 응답·VTI 측 접근은 미검증 |
| 공유된 포트 | 8280 열림(FE 권장), 8281 열림(BE 권장), 8282 열림(SSH), 8283 닫힘(DB 권장) |
| 로컬 PC에서 확인 | 11월 6일 외부 호스트 8282 SSH 로그인 성공. Docker Compose v5.7.0, 실행 중인 컨테이너 없음, 가용 메모리 약 3.9 GiB, 루트 디스크 여유 약 29 GB |
| 아직 확인되지 않은 것 | 외부 HTTPS 443/TLS 인증서, 분석 API·워커 배포와 `/health`, VTI 접근망, 워커 외부 출발 IP, GPU 사용 가능 여부, 디스크 가용 공간 |

8282는 SSH 접속 포트이므로 API 기준 주소로 전달하지 않는다. 8280·8281도 현재 FE·BE용으로 안내된 포트이지 분석 API에 할당됐다는 뜻은 아니다. 시험 API는 가능하면 외부 HTTPS 443의 프록시 뒤에서 내부 `127.0.0.1:18001`로 연결한다. 별도 외부 포트를 사용하려면 VTI와 주소·포트·TLS·방화벽을 먼저 확인한다. DB 포트는 외부에 열 필요가 없다. 메모리 4 GB·디스크 32 GB에서 실제 ATT 전체 분석 및 7일 보관을 검증하기 전에는 성능·용량을 보장하지 않는다.

## 엔드포인트 제공 전 진행할 일

- [x] API 요청·응답 및 오류 정책을 Q15 v1.0 문서와 `docs/openapi.json`에 반영하고 전체 자동 테스트를 실행했다.
- [x] CPU·GPU Docker 분석 워커와 실제 ATT·ATG 전체 프레임의 로컬 실행 기록을 정리했다.
- [ ] VTI가 발급하는 Presigned URL의 실제 유효기간이 DaonH&S 연동 기준인 24시간인지 확인하고, 추가 API 형식 변경 요청이 있는지 점검한다. 형식이 변경되면 Q15 PDF·OpenAPI·결과 Schema·샘플을 함께 다시 생성한다.
- [ ] 11월 16일부터 가능한 전체 통합 연동 시험의 범위를 VTI와 맞춘다: (A) HTTPS 접속·Bearer 인증·작은 샘플 작업, (B) VTI MinIO의 실제 ATT·ATG 전체 분석. 두 범위의 완료 여부를 따로 기록한다.
- [ ] VTI 시트의 ‘11/13 연동 시험’이 일부 API 시험인지 전체 통합 연동 시험인지 확인하고, 최초 회신의 11/16 일정과 조정한다.
- [ ] 11월 4일에 보낸 7개 첨부 파일은 이전 사본이므로 11월 6일 송부 패키지에는 최신 결과 Schema·필드 설명서·샘플·OpenAPI·작업 상태 문서를 다시 묶는다. 실제 비밀키와 Presigned URL은 첨부하지 않는다.

## 서버·네트워크 담당자에게 받아야 할 값

| 항목 | 확인할 값 |
|---|---|
| 시험 서버 | 개발 서버 설치 정보는 위 표에 수신했다. OS·GPU 사용 가능 여부, 실제 디스크 여유, 분석 API·워커 배포 담당자 및 접속 가능일 확인 |
| API 기준 주소 | VTI가 접속할 `https://...` 주소, DNS·TLS 인증서 담당자 및 준비일 |
| VTI → API | 443 포트 접속 방식(인터넷 또는 VPN), 방화벽 허용 범위, 리버스 프록시 연결 경로 |
| 분석 워커 → VTI MinIO | VTI Presigned URL 호스트·443 접속 가능 여부, DaonH&S 서버의 외부 출발 IP |
| 배포 환경 | 영속 볼륨·디스크 여유, API·분석 워커 재기동 방식, GPU 드라이버·컨테이너 GPU 지원 |
| 인증 | 시험용 Bearer 키 설정 담당자와 VTI 백엔드에 별도 전달할 채널. 키 값은 문서·메일 본문에 기록하지 않음 |
| R2-14 정보 전달 | 실제 HTTPS 외부 접속 확인 후 API 기준 주소·워커 외부 출발 IP·Bearer 키 별도 전달 시점을 VTI에 알림. 서버 설치 예정일과 접속 가능일을 구분 |

Compose 기본 API 바인딩은 `127.0.0.1:18001`이다. 이 주소는 서버 내부에서만 열리므로, 시험 서버에서는 HTTPS 프록시와 연결하고 VTI 측에서 접근 가능한 주소를 별도로 마련해야 한다. 분석 워커 자체를 외부에 노출할 필요는 없다. 시험에 사용하는 MinIO URL 호스트는 `HEATPIPE_ALLOWED_SOURCE_HOSTS`에 등록한다. GPU 서버에서는 `compose.gpu.yaml`을 함께 사용하고, GPU를 사용할 수 없는 임시 서버의 CPU 시험은 성능 검증과 구분한다.

## 엔드포인트 제공 전 실제 확인

- [ ] 외부 시험 주소에서 `GET /health`가 200이고 `worker_running=true`다. `GET /version`도 200이다.
- [ ] 운영 구성의 외부 주소에서 `/docs`, `/redoc`, `/openapi.json`은 404다. OpenAPI는 정적 파일로 전달한다.
- [ ] 인증 없는 INT-004 요청은 401이고, 시험용 Bearer 키를 사용한 요청은 정상 처리된다.
- [ ] INT-003으로 작업을 접수해 202·`job_id`를 받고, 동일 `Idempotency-Key`와 본문 재전송에서 같은 ID를 받는다.
- [ ] INT-004에서 분석 워커의 상태·진행률을 조회하고, `SUCCEEDED` 후 INT-001 결과와 모든 후보 PNG를 조회한다. PNG 바이트 크기·SHA-256이 결과 JSON과 일치한다.
- [ ] VTI MinIO를 시험하는 경우, 실제 Presigned HTTPS GET URL로 ATT·ATG를 내려받고 전체 프레임 분석을 완료한다. VTI 측 저장소·네트워크의 소요 시간을 별도로 기록한다.

11월 9일까지 VTI에서 접속 가능한 시험 서버와 HTTPS 경로를 마련하지 못하면 INT-001·003·004 엔드포인트를 제공했다고 보고하지 않는다. 이 경우 11월 6일 API 명세 전달은 진행하고, 11월 16일부터 예정된 전체 통합 연동 시험에 영향을 주는지 확인해 VTI에 준비일과 필요한 일정 조정을 사전에 공유한다.

R2-14의 'T-06에서 확인되지 않은 최초 체크 크기'는 표현이 모호하다. ATT 최대 크기를 뜻한다면 현재 확인된 한 건은 875,667,464 bytes이며 최대값은 추가 실데이터 없이는 확정할 수 없다. 서버 준비 여부와 별도 항목으로 VTI에 의미를 확인한다.
