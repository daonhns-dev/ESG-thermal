# 11월 9일 INT-001·003·004 시험 엔드포인트 준비표

기준일: 2026-11-06. 이 문서는 [Q15 API 명세](Q15_VTI_INTEGRATION_API_FINAL.md)의 **11월 9일 시험 엔드포인트 제공**을 위한 내부 작업표다. 대외 회신 일정은 11월 6일 API 명세 제공, 11월 9일 INT-001·003·004 시험 엔드포인트 제공 목표, 11월 13일 VTI의 Mock 데이터 기반 1차 릴리스와 INT-002·005 엔드포인트 제공 목표, 11월 16일부터 전체 통합 연동 시험 가능 예정이다. 이 저장소의 구현 범위는 INT-001·003·004다. 시험 엔드포인트 제공, Mock 릴리스, 실파일 통합 시험은 각각 확인한다.

VTI의 추가 일정 안내에 따르면 테스트베드 촬영은 11월 9일 이후 시작하고 첫 실데이터는 11월 13~16일 전후로 예상된다. 11월 13일 1차 릴리스는 Mock 데이터로 진행하며, 실데이터 검증은 11월 16일 이후 통합 시험과 UAT에서 진행한다. 따라서 11월 13일을 실파일 통합 시험 완료일로 해석하지 않는다. VTI가 별도로 요청한 기존 실파일 ATT·ATG 1쌍의 사전 공유는 테스트베드 첫 촬영과 구분한다.

8282는 SSH 접속 포트이므로 API 기준 주소로 전달하지 않는다. 8280·8281도 현재 FE·BE용으로 안내된 포트이지 분석 API에 할당됐다는 뜻은 아니다. 외부 443은 기존 공유기 001번 규칙을 따라 `192.168.0.185` nginx로 들어오고, nginx는 로컬 SSH 터널을 거쳐 분석 서버 `10.1.2.2:18001`로 보낸다. `192.168.0.50`은 분석 서버 인터페이스 주소가 아니므로 Docker API 바인딩에 사용하지 않는다. 신규 059번 외부 443 규칙은 기존 001번과 충돌하므로 현 경로에서 불필요하다. 기존 001·002번 규칙은 해당 서비스 담당자 확인 없이 수정하지 않는다. DB 포트는 외부에 열 필요가 없다. 메모리 4 GB·디스크 32 GB에서 실제 ATT 전체 분석 및 7일 보관을 검증하기 전에는 성능·용량을 보장하지 않는다.

사내 PC와 휴대전화 모바일 데이터에서 공개 HTTPS 주소의 `/health`가 응답한다. VTI 시험망에서의 접속과 인증·작업·결과 조회가 확인되기 전까지 VTI 연동 완료로 보지 않는다.

## 11월 9일 이후 전체 연동 시험에서 확인

- [ ] VTI MinIO의 실제 Presigned URL로 ATT·ATG를 내려받아 전체 프레임 분석을 완료하고, 서버 메모리·디스크·처리 시간을 기록한다. 4 GB RAM·32 GB 디스크의 충분성은 이 결과로 판단한다.
- [ ] VTI가 발급하는 Presigned URL 호스트를 `HEATPIPE_ALLOWED_SOURCE_HOSTS`에 등록해 API·워커를 재생성한다. 실제 URL의 24시간 유효기간 적용 여부를 VTI와 확인한다.
- [ ] 11월 13일 Mock 릴리스에서 사용할 결과 JSON·PNG가 현재 스키마(`max_results`, `detected_candidate_count`, 후보별 `roi_temperature_c`)와 일치하는지 VTI 포털과 확인한다. 문서용 Mock 작업은 1개 후보를 제공한다. 기존 T-02 실데이터 샘플의 `detected_candidate_count=null`은 신규 작업의 전체 후보 수가 아니다.
- [ ] R2-14의 ‘최초 체크 크기’가 ATT 최대 크기를 뜻하는지 VTI에 확인한다. 확인한 ATT 한 건은 875,667,464 bytes이며 최대값은 추가 실데이터 없이는 확정할 수 없다.

## VTI 추가 일정·요구사항 확인

- [ ] **기존 실파일 1쌍 사전 공유(Q54):** VTI는 포털 업로드 시간·등록 흐름을 미리 확인하기 위해 테스트베드 외 실제 ATT·ATG 1쌍을 11월 6일까지 요청했다. DaonH&S는 보유한 파일을 11월 9일 면담 때 전달할 계획이다. 요청일과 전달일이 다르므로 VTI에 일정 변경을 미리 알린다. 로컬 검증에 사용한 `20260813_132634.att`(875,667,464 bytes)·`.atg`(151,552 bytes)는 문서상 외장하드 원본이다. 전달 전 파일 접근·공유 가능 여부, 전달 수단과 원본의 위치·촬영 정보 처리 범위를 확인한다. 결과 JSON·후보 PNG 샘플은 이 원본 파일 공유를 대신하지 않는다.
- [ ] **11월 9일 촬영 방식 면담:** 1회 ATT·ATG가 한 구간인지 여러 구간인지, 테스트베드만 촬영하는지 전체 노선을 촬영 후 자르는지, 주야간 촬영 여부, 당일·일괄 업로드 방식, 실제 파일별 용량을 확인한다. 여러 구간을 지나는 1회 촬영이면 포털의 선택 구간 밖 후보를 어떻게 표시·귀속할지 VTI와 정한다. 동시에 130℃의 장비상 의미, ATT·ATG 시각 동기화와 74건 차이, ATG 시간대·GPS 무신호 표기 및 기준 위치 대비 오차를 장비 담당자에게 확인한다.
- [ ] **11월 10~12일 인수 기준:** VTI가 11월 10일 보낼 「요구사항 확정본」의 P0 기능 20개 목록과 Q&A·CR 반영 여부를 대조하고 11월 12일까지 승인 또는 수정 의견을 보낸다. 제안된 Blocker·Critical 0건과 잔여 결함 5% 이하 기준의 분모·심각도·집계 시점을 확인한다. DaonH&S 분석 API 범위와 VTI 포털 범위의 책임도 구분한다.
- [ ] **실데이터 재업로드 UAT:** 11월 13~16일 전후 첫 촬영 데이터가 오면 VTI MinIO URL로 통합 시험을 진행한다. 촬영 횟수가 적을 때 동일 원본을 새 회차로 재업로드하는 시나리오의 `monitoring_data_id`·`Idempotency-Key`·새 Presigned URL·결과 비교 기준을 양측이 정한다. R2-01 상한·중복 후보 품질도 이 실데이터로 검증한다.
- [ ] **CR-06 분석 실패 재시도:** VTI 포털이 실패 상태를 유지하고 원본 ATT·ATG를 재사용할 때, 새 분석 요청에는 새 `Idempotency-Key`와 유효한 새 Presigned URL을 사용한다. 원본이 남아 있어야 재업로드 없이 재분석할 수 있다. 포털 동작·CR 공수는 VTI와 협의 중이며 API의 기존 실패 작업은 그대로 보관한다.
- [ ] **Q40·CR-07 원본 보관:** VTI MinIO의 ATT·ATG 원본 보관·용량 경고·자동 삭제 정책은 DaonH&S의 결과 JSON·PNG 최소 7일 보관과 별개다. 실데이터 1주 확인 후(11월 20일 전후) 원본 용량과 보관 기간을 확정한다. VTI의 ‘약 856MB/회’와 DaonH&S가 확인한 ATT 875,667,464 bytes가 같은 파일·단위를 뜻하는지 확인한다. 실패 재분석 및 UAT 재업로드 전에 원본을 삭제하지 않는 조건도 정한다.
- [ ] **Q59 보고서 첨부:** VTI의 보고서 첨부 제한은 10MB가 아닌 50MB로 정정한다. 이는 포털 기능이며 분석 API의 ATT·ATG 입력 크기 또는 후보 PNG 크기 제한으로 해석하지 않는다.

11월 9일까지 VTI에서 접속 가능한 시험 서버와 HTTPS 경로를 마련하지 못하면 INT-001·003·004 엔드포인트를 제공했다고 보고하지 않는다. 이 경우 11월 6일 API 명세 전달은 진행하고, 11월 16일부터 예정된 전체 통합 연동 시험에 영향을 주는지 확인해 VTI에 준비일과 필요한 일정 조정을 사전에 공유한다.
