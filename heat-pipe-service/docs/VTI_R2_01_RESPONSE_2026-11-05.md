# VTI 2차 검토 R2-01 회신 초안

## 질문에 대한 답변

네. 기존 T-02 실데이터 샘플에는 `max_results=50`을 적용했습니다. 전체 프레임에서 후보 트랙을 만든 뒤 지속성 점수순 상위 50건만 결과에 넣었으므로, 다른 구간의 적격 후보가 결과에서 빠질 수 있습니다. 50건은 전체 탐지 수가 아니며, 기존 샘플만으로 상한 전 후보 수나 구간별 분포를 알 수 없습니다.

## 수정 방향

- 포털의 작업당 **1,000건은 허용 한도**이며 UAT용 분석 결과 상한으로 확정한 값은 아닙니다. 현재 50건은 임시 설정입니다.
- 적격 트랙이 상한 이하이면 점수순으로 전부 반환합니다. 상한을 초과하면 분석 프레임 범위를 동일 길이의 10개 구간으로 나누고, 각 구간의 높은 점수 후보부터 번갈아 선정하는 방식을 구현했습니다. 마지막 결과 순위는 선정된 후보의 전체 점수순으로 매깁니다. 실데이터 결과를 확인한 뒤 이 방식을 UAT 정책으로 확정합니다.
- 차량 부근 후보를 GPS·촬영 시각만으로 자동 제외하지 않습니다. 현재 결과에는 차량 여부를 신뢰할 수 있게 판정할 라벨이나 규칙이 없습니다. 동일 시각·GPS의 여러 후보도 서로 다른 열원일 수 있어 일괄 삭제하지 않습니다.

## UAT 전 확인

실제 ATT·ATG 전체 3,959프레임을 다시 실행해 상한 전 적격 트랙 수, 상한별 반환 후보의 구간별 분포, 동일 시각·GPS 중복, PNG 수와 총 크기, 분석 시간·디스크 사용량을 확인하겠습니다. 각 후보 PNG의 조회·해시·크기도 검증하겠습니다. 이 결과를 바탕으로 UAT 전 상한을 확정하고, T-02 샘플과 관련 문서를 교체하겠습니다. 기존 T-02 샘플 50건과 처리 시간은 이전 설정의 결과이므로 새 방식의 검증값으로 재사용하지 않겠습니다.

현재 로컬 Docker 엔진이 실행 중이지 않고, 기존 원본 ATT·ATG의 접근 경로도 확인되지 않아 위 실데이터 재실행은 미완료입니다. 따라서 본 문서는 **구현 정책 및 회신 초안**이며, 새 후보 분포와 성능을 검증했다고 보고하지 않습니다.
