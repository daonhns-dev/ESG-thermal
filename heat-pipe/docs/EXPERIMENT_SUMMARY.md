# ESG 열수송관 모니터링 데이터 — 탐색 기록 (2026-08-20)

## 배경

ESG 협력업체로부터 열수송관(지하 매설 district heating pipe) 모니터링 데이터를 받음. 차량에 열화상+실화상 카메라를 달고 도로를 주행하며 촬영한 데이터로, 열화상 이미지 기반으로 배관 이상(누수 등)을 탐지할 수 있는지 검증하는 게 목표.

## 1. 원본 데이터 포맷 (역분석, 제조사 문서 없음)

세션 하나당 `.avi`(실화상) + `.att`(열화상 raw) + `.atg`(GPS/타임스탬프) 3개 파일이 동일 파일명(타임스탬프)으로 묶여 생성됨. `E:\열수송관 모니터링 데이터\<날짜>\` 밑에 날짜별로 저장돼있고, 확인한 8/12~8/18 범위에서 총 75개 세션.

- **`.att`**: 8바이트 헤더(`uint16×4` = version, reserved, width=384, height=288) + 프레임마다 `384×288 uint16` LE, 프레임간 여백 없음. 섭씨 = raw값 / 100. 실측으로 30~49°C 범위 확인, 클리핑 없음.
- **`.avi`**: 800×600 RGB, 30fps. **`.att`와 프레임 인덱스가 정확히 1:1 대응** (프레임 수 실측으로 일치 확인) — 별도 시간 정렬 없이 `avi[i] ↔ att[i]` 바로 매칭 가능.
- **`.atg`**: 프레임당 고정 39바이트 레코드 = `[19바이트 ASCII 타임스탬프] + [int32 tag(의미 미확인, GPS 위성수/fix quality 추정)] + [float64 lat] + [float64 lon]`. GPS는 초당 ~1회만 갱신되고 그 사이 프레임들은 같은 값을 공유.
- 세션 중 일부(13개 중 4개, 75개 중 다수)는 **녹화가 비정상 종료**됨 — `.avi` 자체가 없거나, `.att`가 특정 프레임 이후로 전부 0으로 패딩되어 있거나, `.atg` 레코드 수가 `.att`와 안 맞음. 파이프라인에서 자동 감지해 스킵 처리함.

파서: [`datasets/att_atg_io.py`](../datasets/att_atg_io.py)

## 2. 구축한 파이프라인

- [`scripts/build_rgb_thermal_dataset.py`](../scripts/build_rgb_thermal_dataset.py) — 세션별 RGB(jpg)/열화상(npy, raw uint16)/metadata.json(프레임별 timestamp+GPS) 추출. `--thermal-only`로 avi 없는 세션도 처리 가능.
- [`scripts/render_thermal_video.py`](../scripts/render_thermal_video.py) — `.att` → 컬러맵 mp4 (육안 확인용, 학습용 아님).
- 주의: `cv2.imwrite`/`imread`가 Windows에서 한글 경로일 때 에러 없이 조용히 실패하는 버그 있음 — `imencode`+직접 파일쓰기로 우회 처리함(두 스크립트 다 적용됨).

## 3. 이상탐지 방법 검증 — 시도와 실패 원인

### 3-1. 형태 기반(sharp/diffuse) — `scripts/experiments/detect_hotspot_candidates.py` v1

배경 대비 z-score로 국소 열원을 찾고, 원형도/edge sharpness로 "배관 결함(sharp)" vs "노이즈(diffuse)"를 구분하려 함.

**실패 원인**: 카메라가 배관을 근접 촬영하는 게 아니라 **일반 도로를 찍는 대시캠**이었음(RGB 프레임 확인: 신호등, 횡단보도, 주차장 등). 배관은 지하 매설이라 화면에 안 보이고, "작고 동그랗고 경계가 뚜렷한 열원"이라는 조건을 신호등 알림판·차량 하부 엔진열·차량 후미등이 그대로 만족해버림.

### 3-2. ROI 제한 (도로면만 분석) — v2

프레임 하단 45%(도로 추정)만 분석 대상으로 제한.

**부분 성공, 부분 실패**: 하늘/신호등/건물은 걸러졌지만, **도로 위 다른 차량**은 ROI 안에 있으므로 여전히 잡힘(차량 하부, 백라이트).

### 3-3. 프레임 간 추적(움직임 패턴) — `scripts/experiments/track_hotspot_candidates.py`

"고정된 지면 위 이상은 다가가며 커지다 화면 하단에서 사라짐, 동행 차량은 다른 패턴" 가설로 프레임 간 후보를 추적, `area_growth_ratio`+`exits_bottom`+`circularity`로 `likely_ground_fixed` 판정.

**부분 성공, 부분 실패**: RGB 프레임으로 실측 확인한 결과, "고정되고 커지는" 패턴을 만족하는 게 진짜 이상 후보가 아니라 **건물 벽**, **자전거도로 도색(빨간 포장/속도표시)** 이었음 — 이런 것도 물리적으로 고정돼있고 다가가면 커지므로 같은 패턴을 보임. 추가로 circularity(원형도) 필터를 넣어도, per-frame 잔차 blob은 우연히 동그랗게 나올 수 있어서(도색 차선의 국소 조각) 완전히 걸러지지 않음.

**GPS 매칭과 연결한 뒤 재검증**하니 또 다른 패턴의 오탐 발견: **신호대기 등으로 거리가 좁혀지는 앞차**도 "다가가며 커짐" 조건을 만족함 — 진짜 고정 지점과 카메라 기준으로 시각적 구분이 안 됨. 이걸 구분하려면 카메라 캘리브레이션(초점거리/장착각도) 기반 기대 성장률 계산이 필요한데 데이터 없음.

### 3-4. RGB 기반 물체 제외 (시도 안 함)

차량 등 RGB로 감지해서 제외하는 방안을 검토했으나, **RGB(800×600)와 열화상(384×288) 카메라의 화각이 서로 다르고(열화상이 더 좁음, 거리별로 시차도 다르게 나타남 — parallax)**, 단순 크롭/리사이즈로는 정렬이 안 됨을 실측으로 확인(맨홀 랜드마크 기준 크롭 비율 테스트). 제대로 하려면 카메라 캘리브레이션이 필요해 보류.

### 3-5. GPS 기반 반복 통과 비교 — `scripts/experiments/match_gps_passes.py`

같은 날 안에서는 세션들이 연속 주행을 파일 단위로 쪼갠 것뿐이라 겹치는 구간이 거의 없었음(50m 격자에서 1개). **8/13+8/14 이틀치를 합치니 실제로 같은 시간대(오전 9시경)에 같은 구간을 재방문한 사례를 다수 확인** — 정기 순찰 루트가 있는 것으로 보임. 파이프라인 자체는 유효하게 작동함을 확인.

다만 지금까지 확인한 교차-날짜 차이 사례(bin)는 전부 진짜 이상이 아니라 **차량 노이즈**(3-3에서 필터링 시도한 것과 동일 문제)였음.

**추가로 확인된 문제**: 이 GPS(`.atg`)는 일반 민수용 GPS 수신기 실측값이라 **정확도가 5~30m** 수준이고(도심 건물 밀집 지역에서 멀티패스로 더 악화), 게다가 **1초에 1회만 갱신**돼서 그 사이는 직선으로 보간됨 — 도로 커브 구간에서 실제 도로를 벗어나 블록을 가로지르는 것처럼 보임(Google Earth로 실측 확인). 5m 격자로 GPS 매칭한 건 이 오차를 감안하면 너무 촘촘했을 수 있음.

## 4. 근본적인 결론

1. **단일 세션(하루치) 정보만으로는 "원래 있던 고정 요소(도색, 벽, 맨홀)"와 "새로 생긴 진짜 이상"을 원리적으로 구분할 수 없음** — 둘 다 "고정돼있고 다가가면 커지는 열원"이라 모양·움직임 패턴이 동일함. 여러 날 반복 비교가 필수.
2. **배관이 지하에 매설돼있어 영상만으로는 "배관이 어디인지" 특정이 불가능함** — 정상 상태에서 지표면에 아무 시각적 신호가 없음. 볼 게 없으면 찾을 수 없음.
3. 이를 GPS로 우회하려면 **배관의 실제 매설 경로(GIS 좌표)** 가 있어야 하는데, ESG로부터 받은 배관 지도는 보안문서인데다 GPS 좌표가 없는 내부용 도면(도로명 표기도 없이 관경(150A/200A 등)만 표시)이라 좌표 대조가 사실상 불가능했음. 우리 GPS 궤적을 KML로 뽑아 실제 지도에 띄워 역으로 대조를 시도했으나, 지리 정보 부족(담당자가 해당 지역 비거주)으로 결론 못 냄.
4. GPS 자체의 정확도(5~30m, 1Hz 갱신)도 정밀한 위치 매칭엔 한계가 있음.

**결론: 지금 갖고 있는 데이터(도로 전경 열화상 + 부정확한 GPS)만으로는 배관 위치 특정도, 배관 이상탐지도 신뢰성 있게 하기 어려움.** 데이터 자체 품질은 문제없으나(정밀한 온도값, 프레임 단위 GPS/타임스탬프), 촬영 방식(배관 근접 촬영이 아닌 일반 도로 전경)과 위치 참조 정보 부재가 근본 제약.

## 5. 다음에 필요한 것 (재개 시 확인)

- ESG/협력업체로부터 **배관 매설 경로의 GPS/GIS 좌표** (도면이 아니라 좌표 형태로) 확보 — 이게 있어야 "배관 근처 프레임만" 걸러서 분석 범위를 좁힐 수 있음. 이게 프로젝트 진행 가능 여부를 가르는 핵심 전제조건.
- 만약 좌표를 못 구하면: 촬영 방식 자체를 배관에 초점을 맞춘 근접 촬영으로 바꾸거나, RTK급 고정밀 GPS 장비로 재촬영하는 등 데이터 수집 단계부터 재설계 필요.
- (참고용으로 만들어둔 도구들은 재개 시 그대로 재사용 가능: `att_atg_io.py`, `build_rgb_thermal_dataset.py`, `render_thermal_video.py`, `detect_hotspot_candidates.py`, `track_hotspot_candidates.py`, `match_gps_passes.py`, `render_gps_bin_comparisons.py`, `export_gps_kml.py`)
